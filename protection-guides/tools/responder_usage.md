# Responder — захват хэшей через LLMNR и NBT-NS

## Описание
**Responder** — инструмент для перехвата NTLM/NetNTLMv2-хэшей в сетях Windows, используя протоколы LLMNR, NBT-NS и WPAD.
Атакующий отвечает быстрее легитимного сервиса на запросы разрешения имён, вынуждая клиента аутентифицироваться на злоумышленнике.

## Пример использования (Kali Linux)
```bash
sudo responder -I eth0
```
- `-I eth0` — интерфейс для прослушивания.
- При успешной аутентификации жертвы Responder сохранит хэш в логах (`/usr/share/responder/logs/` по умолчанию).

## Сценарий
1. Жертва обращается к несуществующему ресурсу (UNC путь, сетевой принтер, ярлык).
2. Срабатывает LLMNR/NBT-NS-запрос.
3. Responder отвечает как «ресурс».
4. Клиент отправляет NTLM-челлендж-респонс.
5. Хэш сохраняется для оффлайн-атаки или релея.

## На что обратить внимание в SIEM
- События аутентификации NTLM на неожиданные хосты.
- DNS-запросы/LLMNR/NBT-NS к несуществующим именам.
- Логины типа 3 (сеть) с неизвестных IP.

## Меры защиты
- Отключить LLMNR и NBT-NS через GPO.
- Отключить WPAD.
- Требовать SMB signing и LDAP signing.
