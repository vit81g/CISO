# IPv6 Relay (MITM6)

**Источник:** US Cloud, June 2025  
**Новизна в 2025:** Растущий риск из-за включенного по умолчанию IPv6 в гибридных AD-средах; улучшенные техники для перехвата NTLM с последующим релеем.

---

## 🎯 Цель атаки
Использовать автоматическую настройку IPv6 и WPAD в Windows для проведения атаки «Man-in-the-Middle» и перехвата NTLM-аутентификации.

## 📋 Описание
MITM6 — это техника атаки, при которой злоумышленник запускает поддельный IPv6 DHCP/DNS сервер.  
Windows по умолчанию предпочитает IPv6, что позволяет:
- Установить поддельный DNS.
- Отправить жертву на WPAD-сервер атакующего.
- Перехватить NTLM-аутентификацию и релеить её на SMB/LDAP/HTTP/MSSQL.

В 2025 акцент на гибридные AD-среды, где WPAD и автоконфигурация часто включены.

## ⚠ Условия эксплуатации
- В сети разрешён IPv6.
- WPAD включён по умолчанию.
- Нет защиты на L2 (RA Guard, DHCPv6 Guard).

## 🔹 Пошагово в лаборатории
> ⚠ Только в тестовой среде!

1. Запустить MITM6:
```bash
mitm6 -d lab.local
```
2. Запустить ntlmrelayx для релея:
```bash
ntlmrelayx.py -t ldap://dc01.lab.local --add-computer
```
3. Ждать, пока клиенты автоматически подключатся через IPv6 и отправят NTLM-аутентификацию.

## 📊 Признаки в логах и мониторинг
- Логи RA/DHCPv6 Guard (если включены).
- Неожиданные IPv6 адреса и шлюзы на клиентах.
- Event ID 4624/4769 с необычных IP (IPv6).

## 🛡 Меры защиты
- Отключить IPv6, если не используется.
- Включить RA Guard и DHCPv6 Guard на коммутаторах.
- Запретить WPAD через GPO.
- SMB/LDAP signing.

## 🔍 Разбор команд

### 1. MITM6 запуск
```bash
mitm6 -d lab.local
```
- **`-d lab.local`** — домен для поддельных DNS-ответов.

### 2. ntlmrelayx релей на LDAP
```bash
ntlmrelayx.py -t ldap://dc01.lab.local --add-computer
```
- **`-t ldap://...`** — цель релея (LDAP на DC).
- **`--add-computer`** — добавление нового компьютера в AD.
