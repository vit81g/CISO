# LDAP DoS Vulnerability — Crash Active Directory Servers

## 🎯 Цель атаки
Вызвать отказ в обслуживании (DoS) контроллера домена, эксплуатируя уязвимость в службе LDAP (Lightweight Directory Access Protocol), что может привести к сбою или перезагрузке Active Directory Domain Services (AD DS).

## 📋 Описание
В некоторых версиях Windows Server уязвимости в реализации LDAP/LDAPS позволяют отправить специально сформированные запросы, вызывающие чрезмерную загрузку ресурсов или сбой процесса `lsass.exe`, что приводит к перезапуску DC.

## ⚠ Условия эксплуатации
- Доступ к порту 389 (LDAP) или 636 (LDAPS) контроллера домена.
- Нет ограничений на сложность/размер LDAP-запросов.
- На сервере установлена уязвимая версия Windows Server (без соответствующих обновлений безопасности).

## 🔹 Пошаговое проведение атаки (лаборатория)
> ⚠ Выполнять только в изолированной тестовой среде!

1. Подключение к LDAP с помощью инструмента (например, `ldapsearch` или скрипта на Python с использованием `ldap3`).
2. Формирование запроса с рекурсивным поиском большого числа объектов и атрибутов:
```bash
ldapsearch -h dc01.lab.local -p 389 -D "user@lab.local" -w "Passw0rd!" -b "DC=lab,DC=local" "(objectclass=*)" "*" +
```
   - Запрос «*» и «+» вернёт все возможные атрибуты, что создаст высокую нагрузку.
3. Повторная отправка подобных запросов в параллельных потоках (можно через `xargs -P` или скрипт) вызовет перегрузку и возможный сбой службы LDAP.
4. В случае успеха — процесс `lsass.exe` может завершиться аварийно, что приведёт к перезагрузке DC.

## 📊 Признаки в логах и мониторинг
- **Event ID 2889** — неподписанный/незащищённый LDAP bind.
- **Высокая загрузка CPU** на `lsass.exe`.
- Логи сетевых устройств — аномально большое количество пакетов LDAP/LDAPS от одного источника.
- Записи в системном журнале о сбое процесса `lsass.exe` или перезапуске службы AD DS.

## 🛡 Меры защиты
- Установить последние обновления безопасности Windows Server.
- Включить LDAP signing и Channel Binding.
- Ограничить доступ к портам 389/636 на DC только доверенным хостам.
- Использовать средства IDS/IPS для детектирования аномальных LDAP-запросов.
- Включить мониторинг количества и размера LDAP-запросов в SIEM.

## 🔍 Разбор команды ldapsearch

Пример команды:
```bash
ldapsearch -h dc01.lab.local -p 389 -D "user@lab.local" -w "Passw0rd!" -b "DC=lab,DC=local" "(objectclass=*)" "*" +
```

### Аргументы:
- **`ldapsearch`** — консольный клиент для поиска по LDAP (OpenLDAP utils).
- **`-h dc01.lab.local`** — имя или IP LDAP-сервера (контроллера домена). В новых версиях лучше `-H "ldap://..."`.
- **`-p 389`** — порт LDAP (389 для обычного LDAP, 636 для LDAPS).
- **`-D "user@lab.local"`** — DN (Distinguished Name) для bind. В AD можно указывать UPN (user@domain).
- **`-w "Passw0rd!"`** — пароль для bind (лучше `-W` для интерактивного ввода).
- **`-b "DC=lab,DC=local"`** — base DN, с которого начинается поиск. Здесь — корень домена.
- **`"(objectclass=*)"`** — фильтр поиска, совпадает со всеми объектами.
- **`"*"`** — запросить все пользовательские атрибуты.
- **`"+"`** — запросить все служебные атрибуты.

### Почему так в примере:
- `(objectclass=*)` + `* +` нагружает контроллер, так как запрашивает все объекты и все атрибуты.
- Порт 389 используется для упрощения примера, но в продакшене лучше LDAPS/StartTLS.
- Использован UPN для простоты.

### Безопасный вариант:
```bash
ldapsearch -H "ldaps://dc01.lab.local:636" -x -W   -D "user@lab.local"   -b "DC=lab,DC=local"   -E pr=1000/noprompt   "(objectClass=user)" cn sAMAccountName memberOf whenChanged
```
- **`-x`** — простой bind.
- **`-H "ldaps://..."`** — шифрование LDAPS.
- **`-E pr=1000/noprompt`** — постраничный вывод по 1000 объектов.
- Узкий фильтр и ограниченный набор атрибутов.
