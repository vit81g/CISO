# NTLM Relay — релей аутентификации NTLM

## 🎯 Цель атаки
Использовать перехваченную NTLM-аутентификацию жертвы для выполнения действий на другом сервисе от имени жертвы.

## 📋 Условия
- В сети включён LLMNR/NBT-NS или доступен вектор для MITM (DHCP spoofing, WPAD).
- Целевой сервис не требует SMB/LDAP signing.
- Жертва выполняет аутентификацию через NTLM.

## 🔹 Пошагово в лаборатории
1. **Запуск Responder** для перехвата NTLM:
```bash
sudo responder -I eth0
```
2. **Запуск ntlmrelayx для релея**:
```bash
ntlmrelayx.py -t smb://192.168.0.50 --dump-sam
```
3. **Жертва** обращается к фальшивому имени ресурса (`\\fileshare\share`).
4. NTLM-аутентикация релеится на целевой сервер, происходит выполнение команды или извлечение SAM/LDAP.

## 📊 Что видно в SIEM
- Event ID 4624 (Logon Type 3) от имени жертвы с IP атакующего.
- 4776 (NTLM) с нехарактерных хостов.
- 5140/5145 — доступ к шарам от непривычных источников.

## 🛡 Меры защиты
- Отключить LLMNR, NBT-NS, WPAD.
- Требовать SMB/LDAP signing.
- Включить Restrict NTLM.
- Сегментировать сеть и фильтровать egress-трафик.
